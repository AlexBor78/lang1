```
LEVEL 0: ROOT ALLOCATOR
[ROOT ASYNC POOL] (AsyncPoolAlloc, upstream: OS)
    |
    -> Allocates as a single contiguous block

LEVEL 1: GLOBAL STATE (allocating on root pool)
[PROGRAM / TARGETS STORAGE]
    - Contains: Metadata, TargetID list, compilation options
    - [GLOBAL POOL] (PoolAlloc, upstream: ROOT ASYNC POOL)
         -> Purpose: Allocates large program objects
    - [GLOBAL STRINGS POOL] (PoolAlloc, upstream: ROOT ASYNC POOL)
         -> Stores: StringsStorage (guarantees single StringID for "main" across the program)
    - [GLOBAL SEMANTIC POOL] (PoolAlloc, upstream: ROOT ASYNC POOL)
         -> Stores: CoreType table (guarantees single CoreTypeID for "int" everywhere)


THREAD LEVEL 0: THREAD ROOT ALLOCATOR
[THREAD ROOT POOL] (AsyncPoolAlloc, upstream: OS)
    |
    -> Allocates as a single contiguous block

THREAD LEVEL 1: COMPILATION CONTEXT
[COMPILE TARGET] (N independent instances)
    - Contains: TargetID, TargetState, Module (HIR root)
    - [LOCAL REGION POOL] (PoolAlloc, upstream: THREAD ROOT POOL)
         -> Purpose: Complete thread independence. Zero contention with global level
         - [SOURCE ARENA] (monotonic_buffer) -> Raw source file text
         - [AST ARENA]    (monotonic_buffer) -> AST nodes
         - [HIR ARENA]    (monotonic_buffer) -> HIR nodes
         - [LOCAL DATA POOL] (unsynchronized_pool) -> Local Symbols, Scopes, WrappedTypes
```

## Main Idea

divede data to "global" and "tread-local";
global using async-save allocators + mutex
thread-local is sync

global stores global data such as:
- Program struct
- StringsStorage
- some global (marked with`export` keyword) symbols
- TargetsStorage
	(CompileTarget structure is not introduced yet, it will used as main container,
	will remove need in SourcesStorage and UnitsStorage (Target will store it)
	)

thread-local is stored in every CompileTarget instance, such as
- root pool, for evrything there
- SourceFile with it's arena
- TranslationUint(ast) with it's arena 
- Module(hir) with it's arena
- some data wirh it's pool

## Double root pool
the idea of creating root pool, and then "global" pool on top is that:
root pool itself can be on diferend end of memory
so we adding one pool nearby that allocates using root pool
